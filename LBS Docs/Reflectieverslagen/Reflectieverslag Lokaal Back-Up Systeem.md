## Inleiding
In dit document wordt beschreven hoe ik het project "Lokaal Back-Up Systeem" vond gaan, waar ik tegen aan liep en wat ik er van heb geleerd. Het lokaal back-up systeem is een programma dat backups kan maken met gebruik van backupbestanden.

## Wat ging er goed
Toen het project van start ging begon ik redelijk vlot met het documenteren. Hierbij verbaasde het mij hoe snel ik door de documentatie ging. Ik had in een week het Projectplan, Functioneel Ontwerp en het Technisch Ontwerp klaar. Tijden het begin van het bouwen van het project begon ik aan inputs ophalen van de gebruiker, dit had ik al snel voorelkaar. In ongeveer een uur had ik de input van een gebruiker op kunnen halen. Het gebruiken van de programmeertaal "Lua" ging in dit project ook heel goed, de taal was gemakkelijk om te leren en is op zichzelf heel krachtig. Hiermee kon ik heel makkelijk een systeem maken om verschillende functies op te roepen van C -> Lua.

## Wat ging er minder goed
Wat mij heel erg tegenhield met dit project was het gebruik maken van de "Myers Diff" algoritme, ik had de algoritme zelf in Lua geschreven. Maar ik snapte de algoritme niet, dus hier was ik zo'n vijf dagen mee bezig om uit te zoeken hoe het werkte. 

Daarnaast ging het testen ook niet zo goed, ik had een goed testplan geschreven maar was zelf vergeten om te testen. Hierdoor heb ik maar twee keer het programma kunnen testen.

## Wat heb ik geleerd
In dit project is mij duidelijk gemaakt dat het documenteren en het testen van de applicatie een essentieel onderwerp is in het ontwikkelen van software. Elke keer dat ik aan het testen was kreeg ik een nieuw beeld van hoe verschillende gebruikers de applicatie gebruikten. Daarbij kwam ik ook op nieuwe ideen om het programma zo goed/gebruikersvriendelijk mogelijk te maken. Ook heb ik geleerd hoe het maken van backups werkt en hoe programma's verschillende versies van de backups kunnen bijhouden.


## Feedback
Ik heb als feedback van Imholz (de productowner) redelijk veel feedback gekregen. Dit was vooral de werkvolgorde waarin ik aan het werken was, denk hieraan de MoSCoW tabel van Must-haves naar Should-haves naar Could-haves omwisselen. Daarnaast ook een paar potentiële functionaliteiten die ik aan het programma kan toevoegen. Van de testers heb ik vooral veel feedback gekregen dat zij niet helemaal het principe van "backupbestanden" snapten. Hiervoor moest beide keren uitleggen wat een backupbestand inhield. 

## Conclusie
Gedurend project heb ik veel geleerd wat belangrijk is met het maken van software, denk hieraan het werkproces, testen en communiceren. Het programmeren staat ver onder het documenteren van wat je daadwerkelijk gaat maken. Zonder geldige documentatie kan er geen software gemaakt worden. Tijdens het maken van het project heb ik de programmeertaal "Lua" geleerd en een nieuw algoritme dat de veranderingen van twee bestanden kan vergelijken. Ik heb ook veel geleerd wat betreft de documentatie, wat er in verschillende bestanden moet komen en waar ze voor worden gebruikt.
